# miniRAG

## 项目介绍
基于 NumPy 实现RAG检索与生成的最小演示，包括：切分、向量化（text-embedding-v3）、检索（余弦相似度）、生成（检索资料拼接进prompt，调用LLM）。

## 项目结构
1、 build_index.py：构建索引，包括切分、向量化。
2、 query.py：查询索引，包括检索、生成。

## 项目运行步骤
1、本项目通过 DashScope 的 OpenAI 兼容接口（/compatible-mode/v1），调用了embedding模型和LLM模型。脚本中通过环境变量 DASHSCOPE_API_KEY 读取 API Key。运行前设置：export DASHSCOPE_API_KEY="你的key"
2、首先运行 build_index.py 构建知识库（参考资料）的索引，修改脚本开头的path即可，指定md文档的所在路径。注：目前脚本为了简化，只支持md文档，如果需要解析word和pdf等文档，可以通过专门的库，转为markdown格式。
3、然后运行 query.py 查询索引。根据提示输入问题，即可得到检索结果。

## 说明
当前脚本的检索表现与局限：对提及具体景点名、娱乐项目或演出的查询，检索均能准确召回。已知局限出现在"景区有哪些项目"这类宽泛聚合查询——完整答案本就跨多个块（收费项目、服务设施、运营时间表），而包含最全项目列举（含餐饮与免费景点）的"各项目运营时间"块，因正文语义偏时刻表、"项目"仅见于标题，在纯向量候选中排第 14 位（与榜首仅差 0.1），未被纳入 top-3，导致餐饮类设施缺失。这反映双塔检索对聚合查询判别力不足、且 top-k 召回深度有限；生产级 RAG 通常引入 rerank 并扩大召回候选来缓解。
